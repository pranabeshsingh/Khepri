# Raspberry Pi 3 SLM Engine (`pi-slm`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a high-efficiency, low-memory Rust SLM engine (`pi-slm`) tailored for a 1 GB Raspberry Pi 3 to handle piped log analysis, simple weather formatting, and task reminder parsing.

**Architecture:** A lightweight Rust workspace comprising an inference engine (`crates/engine`), a loopback HTTP server (`crates/server`), and a unified binary (`crates/cli`). The engine statically links `llama.cpp` ARM NEON kernels via `llama-cpp-2` to run a 4-bit quantized 0.5B model entirely within ~350 MB RAM, bypassing slow MicroSD read latency during generation.

**Tech Stack:** Rust (2021 edition), `llama-cpp-2` (C++ bindings with ARM NEON SIMD), `clap` (derive CLI parser), `tiny_http` or lightweight standard library HTTP listener, `serde` / `serde_json`.

## Global Constraints

- **Platform Target:** Raspberry Pi 3 (ARM Cortex-A53, ARMv8/ARMv7, 1 GB LPDDR2 RAM).
- **Resident Memory Ceiling:** Total memory usage must strictly not exceed 550 MB RSS under full context load.
- **Compute Concurrency:** Max 3 compute threads by default (`--threads 3`), reserving 1 core for OS/SSH.
- **Context Limit:** 2,048 tokens maximum context length.
- **Security:** HTTP daemon binds strictly to loopback (`127.0.0.1`) and validates `Host`/`Origin` headers against DNS rebinding and cross-origin browser access.
